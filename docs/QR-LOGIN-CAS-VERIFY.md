# 知到二维码登录修复：本次二维码、原版确认、CAS 核验分离

## 问题与原因
此前 Windows 入口 `Zhidao-Task.cmd login` 直接执行 ZHS 0.1.5 原版 `zhs login`。原版收到二维码状态 `1` 后将 Cookie 保存并返回；这表示收到扫码确认，**不等于** CAS 保护的服务器接口一定接受此会话。GUI 随后运行 `doctor-server`，因此可能出现“手机已确认，软件认证不上”。

旧 GUI `查看登录二维码` 仅根据 `~/.zhs/qrcode.png` 文件存在与否打开系统图片查看器，无法区分历史二维码，也无法在原版过期重试生成新图后保证显示更新。

## 修复
- `ZHS-QRLogin.py` 调用安装环境中未修改的 `zhs.login.LoginManager.login_with_qr`，原版 QR 请求、扫码状态轮询、一次性口令、CAS 请求全部保持原样。该程序不是绕过认证，也不伪造服务器会话。
- 启动时移除上一轮二维码 PNG（**不清除**原 Cookie）；原版每次获得新 QR 图片后通过允许值 `ready` 更新状态；`on_scanned` 回调标记 `scanned`；确认后通过 ZHS 自带 `verify_session` 核验服务器会话。
- **二维码自动清理**：本次扫码无论登录成功、服务端拒绝、网络异常、取消或其他退出，Python 都在 `finally` 中删除 `.zhs/qrcode.png`。若扫码进程被强制结束，Windows GUI 检测到任务退出后会再次删除该唯一文件；下一轮登录开始时也会清除上一轮遗留。二维码过期后原版生成的新图会覆盖旧图。 一旦收到手机已扫码回调，就**立即删除磁盘二维码并从 Windows 界面移除图片**，无须等到 CAS 认证结束；原版若再次要求扫码，新图仍可刷新显示。
- 自动清理仅针对 `qrcode.png`，不会删除 `cookies.json`、`config.toml`、课程缓存或整个 `.zhs` 目录；登录状态提示仍可继续显示，不依赖保留二维码图片。
- 服务器已核验为 `OK`：使用与原版相同格式的 Cookie 列表进行临时文件 + 原子替换，结果码 0。
- 官方 CAS **明确拒绝/过期**：不覆盖旧 Cookie，返回诊断码 7。
- 官方 CAS **暂不可达**：保存扫码确认后的 Cookie 以便稍后再进行只读诊断，但 UI 不宣布成功，结果码 4。
- 异常、取消、文件写入失败分别报告固定状态，不包含原始服务器响应、二维码 Token、Cookie、认证链接或账号标识。
- `QrLoginView.ps1` 添加应用内临时二维码窗口，按当前登录会话随机令牌读取数值、阶段和时间戳，不会重复显示旧版二维码；检测到原版二维码 PNG 更新时重新加载图片。
- `Zhidao-GUI.ps1` 显示“获取二维码 → 已扫码 → 手机确认 → CAS 核验 → 成功/待核验/拒绝”，无法仅依据进程退出码宣称服务器认证成功。
- 全部动态状态文件都在应用专属目录，带随机令牌及过期检查。不保存请求、Cookie 或异常文本。

- **关闭主界面保护**：扫码任务仍在运行时，主程序会提示先结束扫码命令窗口，避免继续后台轮询却丢失清理监控。如果进程已退出而界面轮询还没处理完，关闭前会进行一次二维码图片及状态文件清理。
- **界面内存**：二维码仅在等待扫描时显示。手机扫码后，以及单独关闭二维码窗口时，清空 WPF 图片引用（不影响官方扫码状态轮询）。

## 本机验收
1. 使用最新开发包安装（不能用旧 Releases 包），启动设置 → 扫码登录。确认出现**本次生成**的二维码。
2. 使用官方知到 App 扫描，并在手机里确认。设置页应依次显示二维码生成、扫描、CAS 核验，而不是直接显示“已登录”。
3. 验证通过：显示“服务器登录认证成功”，GUI 自动做只读课程接口诊断；即使课程接口失败，**不得**把服务器登录已经成功的事实显示为 Cookie 失效。
4. 认证暂不可用：显示“待核验”，之后使用“连接诊断”；不删除已有凭证，不把网络超时报成二维码过期。
5. 二维码过期后，原版重新生成 QR 时 GUI 应更新，不显示旧二维码；切换登录尝试不得复用上一轮状态。
   任务结束后检查 `%USERPROFILE%\.zhs\qrcode.png` 应已消失；登录 Cookie 和其他文件应仍存在。
6. 若手机已经确认但显示“CAS 未建立有效会话”，需要在原始日志中检查官方登录服务是否真正签发了会话。**请勿上传 Cookie、二维码、一次性口令或完整带敏感参数的日志**。

## 测试和界限
- Python 离线测试使用仿造 ZHS 登录结果，验证 `OK / EXPIRED / UNAVAILABLE`、凭证保存、旧凭证保留、状态脱敏、二维码新旧隔离。
- Windows PowerShell 5.1 测试核验 WPF 控件、状态映射、过期文件、跨会话 token；CI 也构建新的 Windows EXE。
- 无法仅靠离线测试证明官方服务器当前可用，也无法保证真实扫码会返回 `1`。真正的二维码登录还需用户在 Windows 上实测。
