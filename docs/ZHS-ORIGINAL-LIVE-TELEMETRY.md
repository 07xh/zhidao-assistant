# ZHS 原版模拟进度 · 只读实时监控补充（方案 B）

本次只增强 **07xh/zhidao-assistant** 的监控显示，**没有**修改上游 `pjm314159/zhs v0.1.5` 的模拟播放算法、进度上报请求、频率、异常处理或自动重试行为。

## 已核实的原版输出
- `src/zhs/ai/video.py` 的 `AiVideoPlayer.play_video` 会以回车覆盖的方式输出 `playing [进度条] 48.5%`；该百分比以当前模拟播放段的起止位置为基准，**不是完整视频时长比例、更不是整课完成率**。
- `src/zhs/ai/course.py` 会输出 `处理资源 2/5` 等资源序号；它是当前知识点的资源处理序号，并不代表整门课所有资源进度。
- 原版在调用上报后，无论 `_report_video_progress` 返回成功还是失败都可能继续打印本地进度条，因此不能由 `playing` 推断请求成功、学习记录更新或已完成。

## 实施结构
- `payload/ZHS-ConsoleMonitor.py`：调用已安装的 ZHS Typer 入口 `zhs.__main__`，用标准输出透传方式观察 `playing` 和 `处理资源 n/m`；用户原控制台照常显示。仅将限界百分比/资源序号/随机监控令牌/时间戳写入本机单次任务快照，**不写原始控制台日志、响应、Cookie 或课程名称**。任务结束即删除快照。
- `payload/Zhidao-Task.cmd`：GUI 传来一次性随机令牌时启用只读控制台观察；缺少观察器时保留原来的 `"%ZHS%" play -c ... --type ai` 执行方式。观察器运行后不进行失败重试，避免重复提交。
- `payload/HeartbeatMonitor.ps1`：校验令牌、时效、百分比、资源数范围；过期、坏数据直接拒绝。
- `payload/Zhidao-GUI.ps1` 与 `payload/HeartbeatView.ps1`：仅显示与当前课程及会话相匹配的快照；账号切换或课程切换不显示旧状态；原版任务退出后清理文件。
- `payload/Zhidao-UI.xaml`：在服务器学习记录之外独立展示「ZHS 原版 · 本地模拟片段」进度条、百分比和「当前知识点资源 i/n」，并明确注明**仅本地模拟运行记录、不是实际观看或服务器进度**。

## 验收
- Python 离线测试：验证 ANSI 彩色进度、CR 刷新、资源切换重置、异常数值与敏感文本不进入 JSON、原版 CLI 参数不变、退出删除。
- Windows PowerShell 5.1：新鲜随机令牌快照解析、超时和错误数值拒绝；WPF 虚拟课程展示，服务器进度保持独立，切换课程清零。
- CI 编译与安装清单：确认 Python 监控文件已打包、原有 ZHS 调用仍在、PowerShell 不产生解析错误。
- Windows 实机未验收：是否正确接收不同终端编码/颜色、实际 ZHS 0.1.5 CLI 兼容性、课程进度读取仍需真机验证。本功能**不保证或代表**学习进度可被服务器记录。

## 已知界限
- 原版没有明确输出上报回执成功状态；UI 不提供猜测的「成功心跳次数」或「发送成功率」。
- 原版未输出当前真实视频长度时不能推算观看秒数；进度条只展示当前原版模拟片段。
- 若原版后续修改输出格式，实时进度可能显示「等待原版输出」，不会生成估计值。
