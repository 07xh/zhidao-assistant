# 学习状态监控 · 方案 B（第一轮工程实现）

## 本轮目标
在现有知到助手 WPF「课程详情」中，展示互相独立的三个来源：本机任务生命周期、官方 HTML5 播放状态、服务器只读学习记录。该功能仅做观察和状态归一化，**不修改 ZHS 0.1.5 的心跳发送机制、次数、节奏或学习时长**。

## 真实代码落点
- `payload/HeartbeatMonitor.ps1`：纯 PowerShell 5.1 状态模型；会话轮换立即清除事件；课程键区分智慧课程教学班、共享课原始路由；事件文本固定白名单且内存缓冲最多 48 条；本地播放器快照必须是当前一次性 Token、允许的播放事件、18 秒内的新鲜数据。
- `payload/HeartbeatView.ps1`：WPF 只读渲染；不读取原始 stdout、stderr、Cookie 或请求体；本地位置和服务器记录分别计算，知识点满进度比例不等于课程总进度。
- `payload/Zhidao-UI.xaml`：课程详情右侧的摘要状态卡、服务器记录条、可展开的本地播放位置和事件日志；整页右侧可滚动，不覆盖课程内容。
- `payload/Official-Player.ps1`：仅在官方 HTTPS 域名的 WebView2 播放观察事件到达时，向本机用户目录写入严格脱敏短期状态快照；不接触平台心跳请求。
- `payload/Zhidao-GUI.ps1`：在原有启动、退出、排队核验和核验完成节点通知状态模型；不改已有 CLI 执行参数或进度读取接口；每 3 秒重绘监控状态并执行原先的缓存刷新。

## 当前观测的真实性边界
1. **原版 ZHS**：当前只能观测到本机进程是否启动、退出，以及只读进度核验是否完成；没有逐条网络事件源，所以 UI 显示「原版心跳不可观测」，不计算伪造的心跳成功次数。
2. **官方 WebView2**：支持本地 HTML5 `positionSeconds/durationSeconds`、播放/暂停/缓冲/位置跳变等状态。仅能代表本地播放器的观测值，不能证明服务器计入学习时长。
3. **服务器进度**：共享课展示「完成视频数量 / 视频总数」，智慧课程展示「满进度知识点数量 / 知识点总数」。它们都不是平台的总课程完成率，不能与本地播放进度合并成一个进度条。
4. **安全和隔离**：监控事件仅内存保存，不写凭据或原始响应。刷新前校验课程键和 HMAC 会话指纹；账号切换清理旧事件；短期本地播放快照在窗口关闭后删除。

## CI 与真机验收
- Windows PowerShell 5.1：语法解析与独立模块的合成课程、合成会话、旧会话拒绝、课程隔离、虚假状态拒绝、新鲜本地播放数据、超时数据拒绝。
- Python：XAML 元素存在性与合法性、连接流程、既有 ZHS 命令、状态白名单、无新增发送代码。
- 旧回归：登录、Cookie 文件直接输入、课程缓存、视频控制器、安装包清单及 Windows x64 交叉构建。
- **尚待在使用者 Windows 真机逐项核验**：监控展开/收起、窗口尺寸 940×650、官方 HTML5 状态刷新、窗口关闭自动清理、原版任务退出的待核验时序、断网、切换登录账号。CI 通过不等于真机的实际登录/播放/服务器进度已验收。
